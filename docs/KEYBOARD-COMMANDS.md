# Keyboard commands, selection and undo/redo

Refs UB-36. Status: phase A (pure model and isolated UI) and phase B (wiring into the app) on
`feat/keyboard-registry-UB36-20260929`.

## Goal

One command registry drives keyboard dispatch, context menus, the ⌘K / Ctrl K
palette, the ⌘/ / Ctrl / help with visible keycaps, and per-device remapping.
Escape dismisses one layer at a time. Shift-click and Shift+J/K select ranges.
Undo/Redo reverts saved task changes without touching native text undo and
never overwrites a newer conflicting server version.

## Decisions

- **Registry in `shared/lib/commands.ts`, catalog in `shared/lib/command-catalog.ts`.**
  These are pure data and functions, so every layer can read them without cross-slice imports.
  Handlers are attached at dispatch time in `features/keyboard` (phase B) and
  never stored in the registry.
- **Canonical binding text** (`Mod+Alt+Shift+K`, sequences separated by a space)
  is both the storage format and the equality key. `Mod` rather than `Meta`/`Ctrl`
  lets one stored override work across the user's platforms. Rejected: storing
  `KeyboardEvent.code`, because it breaks shifted punctuation such as `?`.
- **Shift is implied by punctuation.** `?` matches Shift+/ on US layouts, and
  `Shift+/` is rejected as ambiguous. Letters and named keys keep an explicit
  Shift.
- **Physical-key fallback** is used only for letters and digits under Option/Alt/Mod,
  or when the layout yields a non-Latin letter. It never applies to punctuation, whose
  position differs by layout.
- **Text-entry rule** replaces per-command exceptions: only modifier bindings of
  `allowInTextEntry` commands fire in fields. Native text undo therefore keeps `Mod+Z`
  inside fields with no special case.
- **Remap records one combo.** Defaults may be sequences (`G I`). Rejected: a
  sequence recorder, whose timing is hard to make accessible.
- **Per-device persistence**, per AGENTS.md: UI preferences live in Zustand.
  Server sync of bindings is out of scope and needs a user decision.
- **Field-level undo conflicts.** A newer version that changed other fields
  does not block undo; one that changed the undone field does. Rejected: blocking
  on any version bump, which would make undo useless while live updates arrive.
- **Remap UI lives in `features/preferences`.** It shares the store without a
  cross-slice import and is mounted as Settings → Keyboard (`?tab=keyboard`).
- **Handlers attach at dispatch, in three places.** `app` passes the global handlers that need
  other slices (palette, undo/redo); `features/keyboard` owns help, navigation, task creation and
  the page-context Escape; a page registers its own handlers and its selection layer
  (`usePageCommands`) while it is mounted. A command with no handler does
  nothing and never calls `preventDefault`. Rejected: storing handlers in the registry, which
  would pull React and routing into `shared`.
- **Focused-row commands** (`target: 'focused'`: Enter, Space peek, Shift+F10) are listed in
  help and take part in conflict detection, but the focused row or menu handles them, so they
  are fixed and never enter the global keymap. Enter and Space are browser-reserved keys for
  every other command.
- **Overrides reach `shared/ui` through `KeyBindingsProvider`.** Keycaps in menus, help and the
  palette read the same effective bindings the dispatcher uses, without `shared` importing a
  feature.
- **Surfaces own their keys.** While a dialog, menu, listbox or preview is open, global
  shortcuts do not fire and Escape is left to the surface. "Open" excludes retained popups that
  are `hidden`, `inert`, closing or have no client rects, so a popup kept mounted after closing
  cannot swallow the next Escape.
- **Undo scope is task properties.** Title and description keep their own editor undo, draft
  and conflict flow; undoing them from outside the editor would race that flow. Each saved
  property PATCH from `useIssueUpdate` records one step; the undo PATCH itself is not recorded.
  The step is planned against a fresh `GET`, so a stale cache cannot hide a newer server value,
  and the PATCH carries that version, so a write that lands in between still gets the server's 409. The history lives in memory for the tab; it is not persisted.
- **Mac vs Windows keys** follow `navigator` platform detection once per page load; e2e sets
  the platform with an init script to check both. Other specs press the modifier of the device
  the browser emulates (`commandModifier` in `tests/e2e/session-fixture.ts`): Desktop Chrome
  reports Windows and Desktop Safari a Mac, whatever the host is, so Playwright's host-based
  `ControlOrMeta` would press the key the app ignores.

## Out of scope

Server-synced bindings; recording sequence shortcuts; multi-entity (bulk) undo;
undo of create/delete/comment and of title/description edits; bindings for board
drag-and-drop; range selection on the board view.
