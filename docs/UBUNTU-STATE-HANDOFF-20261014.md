## Identity continuation (first pass) — changed files

- `src/pages/issue-new/state-lib.tsx` — `NewIssuePage` reads `useMe()`; without an identity it renders an `aria-busy="true"` placeholder (no editor, no controller, no storage access). With an identity it computes `draftKey = issueDraftKey(me.workspace_id, me.id, incoming)` and renders `<IssueDraftPage key={location.key + '|' + draftKey} me draftKey incoming />`. `IssueDraftPage` now takes `{ me: Actor; draftKey; incoming }` and no longer reads identity or location itself. `Actor` type imported from `@tickets/contracts`.
- `tests/unit/state-issue-identity.test.tsx` (new, 2 tests) — busy placeholder without identity; editor with identity.
- `tests/fixtures/issue-draft-lifecycle/main.tsx` — fixture with account A/B buttons, same-identity refetch, identity reset, page toggle, deterministic created-count signal.
- `tests/state-issue-identity-browser.mjs` — 10 real-page scenarios; API interception is a predicate matching only `origin === fixture origin && pathname.startsWith('/api/')`, so Vite module URLs are never intercepted. Scenarios resolve deferred responses explicitly; no timers.
- Untracked request files (`STATE-*-REQUEST.md`) and this document are not source.

## Root cause

`useDraftController` builds its controller once (`useState` initializer) with the key of its first render. `NewIssuePage` only remounted on `location.key`, and `useMe()` could be empty on first render, so the key could contain empty workspace/user ids. After an account or workspace change the same controller (private text, persisted attempt, in-flight request authority) stayed mounted under the old identity, and a draft saved under the other account was not reloaded. Late responses already settle by their own key/expected record (`settleStored`); the defect was controller ownership and key construction, not settlement.

## Fix semantics

- No controller is constructed until a genuine identity exists (placeholder shows nothing private and writes nothing).
- Any change of account, workspace or draft key (defaults) changes the React key, which remounts `IssueDraftPage`; `useScope` deactivation disposes the old controller (existing microtask/StrictMode-safe path unchanged). The new controller loads that identity's own saved draft.
- A refetch returning the same ids keeps the key: no remount, focus/caret/text preserved.
- No new store; uses existing `useScope`/`useStore`/`useLatest`/`sessionStoragePort` primitives. Imports go through existing public slices; no new cross-layer imports.
