# Linear live synchronization — activation boundary

Tasks remains the operational backend and Linear assigns final ticket codes. The completed numbering migration is not repeated.

This release activates bidirectional issues, comments, projects, documents and initiatives, with durable signed source inbox, native outbox, generation/entity leases, preserved conflicting content, canonical code assignment, source removal markers and bounded managed queue delivery. Source metadata is imported as dependencies. Native comments must have a verified compatible source author; the runtime never impersonates other people. These supported paths have explicit replay, concurrent-creation, revocation and real PostgreSQL tests.

## Explicit remaining capability gaps

Native labels, workflow statuses, cycles and milestones now enqueue durable changes and are exported using stable UUIDs and verified parent mappings. Native scans cover these families as well as issues, comments, projects, documents and initiatives. Their regression tests exercise real HTTP creation, queue insertion and schema-valid source requests. Both operator helpers have been applied and verified; neither remains an activation prerequisite. References whose parents have not yet been exported remain visible as pending work rather than being silently dropped. This release is not a claim of full source-API feature parity.

Some source APIs cannot represent native archive or relationship edits directly; unsupported changes remain explicit errors/conflicts. Original content, creation metadata and history are retained. Unsupported does not mean synchronized. The status endpoint must be inspected during activation; repair/conflict handling remains required.

## Review findings closed for this release

Source team moves validate team/status/reference consistency and apply source codes in one transaction. Obsolete deployment or generation deliveries return without claiming or emitting jobs. All native creation paths preserve a durable original creation intent, so a later local text edit cannot wedge an already-created source UUID. Native edits coalesce per entity and an edit arriving during processing survives both success and failure. A new dispatch token distinguishes subsequent native edits; source retries include attempt identity.

Target-ID lookups remain a documented scaling improvement. Read-only production EXPLAIN measured 0.924 ms execution with 6,959 mappings. No unapproved schema or index mutation was substituted for a migration.

## Operational validation

Use a clean merged candidate, test real `/api/ready`, authenticated sync status/configuration and signed delivery, then configure the exact deployment as the only writer. Keep the existing source webhook disabled until receiver and managed queue consumption succeed. Verify a disposable task/comment in each direction and matching UUID-linked codes; preserve or archive test artifacts instead of deleting source history. On a failed acceptance, pause configuration and webhook, retaining inbox/outbox evidence.

The published API status and actual test receipts, not this document, establish whether synchronization is enabled.

## Team-scoped labels and open problem rows

Native labels are unique per workspace by name. Linear scopes a label to one team or to the workspace, so the import binds same-name labels of several Linear teams to one native label; production had seven (`Infra`, `session:6`, `session:main`, `agent`, `session:4`, `session:default`, `session:conloca-app`). Issue writes to Linear (update and create) resolve each native label for the issue's source team from the stored source record of each alias: that team's label, else a workspace label, else a record that never stated its scope (older imports stored labels without `team`); another team's label is never sent. Within the chosen group an archived alias loses a tie. None → `SYNC_LABEL_TEAM_UNAVAILABLE`; still several → `SYNC_SOURCE_ALIAS_AMBIGUOUS`. Both block the job before any source write. Earlier the first mapping row was sent regardless of team, Linear rejected the write, and about 70 HYP issues stayed blocked as `SOURCE_QUERY_REJECTED`, or a new task kept its `PENDING-` key. Tests: `tests/unit/linear-label-team-alias.test.mjs` (fake Linear transport that rejects another team's label as `INPUT_ERROR`). The stored record is the one first seen for that source UUID; a label Linear later moves between team and workspace keeps its recorded scope until the record is refreshed. Native team moves are not an API operation today; if one is added, its label write must use the destination team.

Every reconcile pass, webhook delivery and native edit enqueues its own job for an entity. Only the most recently finished outcome of an entity stays open. Each job reads both sides afresh when it runs, so a job that converges, blocks or fails moves the `blocked`/`failed` rows of that entity that finished before it to `superseded` (the row keeps its error and names the retiring job). A run that decides nothing (a stale source read, an older lifecycle event, an out-of-scope entity) retires nothing. An entity is its collection plus source UUID, or plus native UUID for native-side rows, because a native job on an ambiguous alias has no single source UUID; once an operator resolves the alias, the next native job therefore still retires that row. A signed source removal retires the entity's earlier rows as well, since no later job would; removal rows themselves carry delivery proof and are never superseded. The next reconcile retries each blocked entity once, clears it once it converges, and a persistent rejection shows as one row instead of one per pass. `superseded` rows are retained like `done` rows and counted under `counts.superseded`; `problems` lists only open rows. Rejected alternatives: stable per-entity scan keys (would also have needed a separate clean-up of the existing per-pass rows), bulk `/sync/linear/retry` of every blocked id (reprocesses each entity once per stale row and spends the shared Linear request budget), and ordering by job creation time (an older job retried later observed newer state than a job that finished before it).

Out of scope: creating a missing team label in Linear on demand, choosing a source label for native edits of an aliased label itself (still `SYNC_SOURCE_ALIAS_AMBIGUOUS`), and dispatch priority of user-created tasks over reconcile fan-out (UB-87: blocked rows are never dispatched, so they do not hold back a new task's create; the reconcile backlog ahead of it does).
