## Decisions

**One action source (P6, P11).** A task's contextual actions are built once by `useTaskActions` in `features/issue-edit`: Open task, Status ▸, Assignee ▸, Copy ▸ (shared `copyActions`: link, task ID, title, Markdown, linked title, branch name, prompt) and Select/Deselect. The same array feeds the preview toolbar, the preview's More menu, right-click, Shift+F10/ContextMenu key, and touch hold. `MenuAction` gains `choice` (a single-choice list rendered as radio items in menus and as the existing `Picker` in the toolbar) and `toolbar` (short label + icon for promotion into the capsule). The toolbar's Status and Assign keep the compact `Picker` (one tap, current value checked, as on PDF p.23–24 and p.45); the UB-30 searchable `Combobox`, merged alongside, is the list row and board card assignee control. Rejected for the preview: the Combobox, whose search field would sit inside the lifted card for a list of a few statuses or people.

**Which gesture shows what.** Following the desktop reference, right-click and Shift+F10 open the contextual _menu_ (the full action list at the pointer, or under the focused row), and Space, the row ellipsis (click, 500 ms hover) and a hold open the _preview_. The preview's More button opens the identical menu. This changes the 12 September README contract, where right-click opened the preview; the 18 September context-menu acceptance cases (ported here) asked for a menu, and the user's desktop reference shows the same split. Visible ellipsis menus on team, saved-view and document rows now also open on right-click and Shift+F10, and team and saved-view rows on a hold, through `ContextRow`.

**Document rows are links.** Right-click on a document row still opens its menu (the 18 September case; Linear's desktop app does the same on its row links; the menu has Open and Copy ▸ link, and Cmd/Ctrl/middle-click still open a new tab). On touch, a hold on a link is the browser's gesture: the hold never starts on a link, and Android's long-press `contextmenu` there is left alone, so the browser's link menu opens; the row's visible ellipsis carries the actions. Rejected: cancelling that `contextmenu` (a long-press then did nothing at all) and starting the row hold on links (it would take the link's own long-press away).

**Right-click menu on task rows.** Task rows have no visible ellipsis menu (their ellipsis opens the preview), so `ActionMenu` renders a `hidden`, `aria-hidden`, untabbable Base UI trigger for them. Base UI links a menu into its floating tree through a trigger; without one, opening Copy ▸ looked like a sibling menu opening and closed the whole menu. The hidden trigger also names the menu (Base UI points `aria-labelledby` at it). On close, focus returns to the element that was focused in the row when the menu opened; if none was, focus is not moved, and never onto the hidden trigger. Rejected: ignoring Base UI's `sibling-open` close reason, which would leave the submenu outside the root's tree for outside-press and focus handling. A press on a menu item never starts a row hold: the menu is portalled, and React bubbles portal events through the row, so a hold starts only from the row's own DOM.

**Phone presentation (P10, P12, P13).** Below 768px the preview is a lifted card, not a 344px popover: inset 12px plus the safe area from the left, right and bottom edges, as wide as the screen allows, growing upward to at most the viewport minus the safe area and a 60px gap at the top. A dim scrim covers the page; tapping it dismisses without activating the row underneath. Reasons: p.15/p.45 present every contextual surface this way; a bottom-anchored card keeps the capsule in thumb reach and never jumps when the description loads; and a 344×378px popover could not give long content half its height with five 44px actions. Desktop keeps an anchored 420px popover beside the ellipsis, placed below or above, whichever has room.

**Content first.** Header: task ID and a round close button. Then the title, compact property chips (status, priority, assignee, labels, project, due date), the full Markdown description (no 2000-character cut; it scrolls inside the card) and attachments (name, size, link to the private content route). The capsule stays pinned below the scrolling content.

**Toolbar.** One `role="toolbar"` capsule with Open · Status · Assign · Copy · More, icon over a short label on phones and icon beside it on desktop, 44px touch targets. Arrow Left/Right, Home and End move between actions; Arrow Down opens a picker or menu (APG toolbar pattern), so the old vertical Up/Down movement is dropped. Pickers and menus render inside the preview layer, so an outside tap, Escape and focus treat them as part of the preview.

**Layers opened from the content.** `usePreviewLayer()` returns the preview's portal layer. A popup opened from the preview content, such as the UB-77 person card, portals into it: `.peek-layer .popover-positioner` stacks it above the surface, and a press inside it is not an outside press. Escape leaves the preview open while any trigger inside it carries Base UI's `data-popup-open`, so the nested popup closes first. A click that changes `location.href` (a link in the content) and `popstate` close the preview without returning focus, because the page it previewed is gone.

**Motion (P13).** Enter and exit are CSS transitions of `opacity` and `transform` only, from `@starting-style`, with `transform-origin` set to the pointer or ellipsis position relative to the computed placement. Closing keeps the surface mounted with `data-state="closing"`, `aria-hidden` and `inert`, then unmounts after its transitions finish. Reopening during the exit flips the state back on the same element, so the running transitions reverse from the current frame instead of restarting. Placement is computed once when opening from the source rectangle, the viewport and measured `env(safe-area-inset-*)`; nothing is read per frame. Reduced motion removes the transforms and the exit delay.

**Hold (P3, P4, P5).** `trackHold` (shared/lib) owns the gesture for the preview and for `ContextRow`: 340ms threshold, 10px slop, `data-pressing` progress on the source (a spring transition, so release and cancel spring back), cancellation on movement, pointercancel, scroll, blur, `visibilitychange` to hidden and a new text selection. A cancelled press or a completed hold marks only its own click to be consumed; the next pointerdown clears the mark, so there is no time window. Holding the assignee avatar with touch opens the preview with focus on Assign; a mouse press on the avatar still opens its picker directly.

**Board cards (UB-43, UB-77).** A board card is a wrapper, not a button: the open button fills it and the assignee control sits beside it at the footer's end, where the avatar was, because a combobox cannot nest inside a button. The board takes the page's `assigneeControl` (the list rows' `IssueAssignee`, with the same viewer permission), so a person card added to that control reaches rows and cards alike. A touch hold on the control opens the preview at Assign through `data-hold-action` on its wrapper; a mouse press opens the control itself. Test: task-preview `a board card holds its open button and assignee control side by side`.

**Space (P7).** Space on a focused task peeks, and the shortcut help lists "Space — Peek into the focused task" and "Shift+F10 — Actions for the focused item". Both entries now come from the UB-36 command registry (docs/KEYBOARD-COMMANDS.md) as focused-row commands.

## Out of scope

Full PDF parity (UB-33), the configurable shortcut registry (UB-36), task deletion or other destructive actions in the preview, and bulk actions. No API, schema or permission change: status and assignee use the existing versioned `PATCH /v1/issues/:id` with its optimistic update and rollback, and viewers see them disabled.
