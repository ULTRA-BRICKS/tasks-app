# Phone pages never drift sideways

User report (UB-32 / 22f093fd-1266-45a3-a2d6-96a8a1d6ac68): on an iPhone, task details and their popups drift sideways, for example on task a76cc660 (GL-272). That task's body is an empty ticket template, so it cannot show which content causes the drift. The causes below were reproduced on synthetic data: long assignee names and emails, unbroken URLs, code blocks, GFM tables, dates, and every popup on the task page. Earlier layout work is in [PEOPLE-AND-PHONE-LAYOUT.md](PEOPLE-AND-PHONE-LAYOUT.md).

Folded in: the ticket "Estimate picker opens 256px content shift and runs under the dock in WebKit phone" (9aaaf79e-1b24-49c0-9ae4-ff47b0809ebd). At 390×844 in WebKit, the Estimate trigger moved from 608 to 864 px with `scrollY` still 0, and its popup (518–858 px) ran past the viewport and under the dock (784–840 px).

## Contract

On a touch phone at visual scale 1, for widths 320, 375, 393 and 430 px in Chromium and WebKit:

- The root never scrolls horizontally: `document.documentElement.scrollWidth ≤ clientWidth + 1`.
- `scrollX` stays 0 through all of these:
  - vertical scroll to the top, middle and bottom of a long task;
  - focusing the title, the description, the comment box and the start and due date inputs;
  - opening every property picker, both calendars, the cycle hint, the task actions menu and its Copy submenu, a person card and the task preview;
  - an explicit `scrollTo({ left: 200 })`.
- Nothing is hidden by clipping. Every element of the task panel lies inside the viewport, unless it sits inside an explicit horizontal scroller.
- Only these regions scroll horizontally: the board region, Markdown tables (`.tableWrapper`) and the activity diff box. Code blocks wrap, following the global `pre { white-space: pre-wrap; overflow-wrap: anywhere }` rule, so their text stays visible.
- A task page does not move under the reader once shown. The properties below the description keep their place when the description editor arrives, and opening a picker leaves the trigger, `scrollX` and `scrollY` where they were.
- Popups stay inside the visual viewport, outside the safe-area insets and above the phone dock:
  - Every Base UI positioner uses `usePopupCollisionPadding()`: 8 px plus that side's `env(safe-area-inset-*)`. At the bottom, the larger of the inset and `--fixed-chrome-bottom` is used; the phone layout sets that variable to `--mobile-dock-reach`, the navigation bar's reach: 4 px edge + the 56 px dock as rendered + the bottom inset. `--mobile-dock-clearance` (page end padding, scroll-into-view inset) is derived from the same token.
  - Popup widths are limited by Base UI's `--available-width`, and heights by `--available-height`, which already account for that padding. A popup near the dock opens upwards or shrinks and scrolls its list, so its last option stays reachable.
  - The task preview is drawn over the dock and is exempt from the dock rule; UB-38 owns its phone placement. The menus of its toolbar still use the shared padding, so on a short screen they stop below the notch.
- Pinch zoom stays available:
  - The viewport meta is `width=device-width,initial-scale=1,viewport-fit=cover`, with no `maximum-scale` and no `user-scalable=no`.
  - No root `touch-action` blocks pinching.
  - Touch inputs are at least 16 px, so iOS does not auto-zoom when they get focus.

Every measurement injects `html, body { overflow-x: visible !important }` first. This way, a clipping rule on the root can never hide a real overflow source from the tests.

## Decisions and rejected alternatives

- **Rejected: keep or replace `overflow-x: clip` / `hidden` on `html`/`body`.** Clipping hides content that can't be reached (the right-hand columns of a description table were cut off and couldn't be scrolled to), and WebKit still panned on focus.
- **Rejected: wrap table cells anywhere so the table fits 320 px.** A six-column table became unreadable 40 px columns that were hard to edit. Tables are an explicit horizontal-scroll region instead.
- **Rejected: horizontal-scrolling code blocks.** The existing global `pre` wrapping keeps all code visible without a nested sideways scroller on a phone.
- **Changed: tables in read-only Markdown use the same scroll region as the editor.** Squeezing them to fit kept the page still, but made headers unreadable.
- **Rejected: `maximum-scale=1` / `user-scalable=no` to stop focus zoom.** Pinch zoom is an accessibility requirement; 16 px touch inputs already avoid focus zoom.
- **Edges are read with a probe element.** `usePopupCollisionPadding()` measures the resolved padding of a hidden fixed element, so `env()`, `max()` and `calc()` resolve as the browser sees them. This is the same approach as the task preview. The measurement runs when the first popup owner subscribes, never during render; until then only the 8 px edge applies. The values are cached, and subscribers re-render only when an edge actually changes (for example on rotation or when crossing into the phone layout), not on every `resize` fired by the collapsing address bar.
- **The dock reserve is a CSS variable, not a measured rectangle.** The dock animates between expanded and collapsed and slides away for the software keyboard; a rectangle read on resize would be stale. The variable covers the dock's tallest state.
- **Rejected: reserve the description's height in the placeholder.** The height depends on the content and the width, and is unknown until the editor renders it.
- **Rejected: a read-only Markdown placeholder.** react-markdown and Tiptap lay out headings, task lists and tables differently, so the swap still shifts the page, only by less.
- **Rejected: one route-level Suspense boundary.** On desktop the task opens in a panel beside the list; suspending the route would blank the whole list on the first open.
- **The editor chunk starts loading when a page that needs it mounts,** in parallel with that page's data. Only the first page of a session can wait longer than its data; later pages find the chunk loaded.
- **An error does not wait for the editor chunk.** A page that cannot load (missing, forbidden, server error) has no description to lay out, so its error state shows as soon as the data request fails, even if the chunk is slow or never arrives.

## Out of scope

- The task preview's phone placement belongs to UB-38; that branch insets the preview by the safe area. This spec only asserts that the preview stays inside the viewport.
- The Estimate ticket's physical iPhone Safari check against production is tracked in UB-83.
- Landscape phones: the collision padding covers the left and right insets, but there is no dedicated landscape layout pass.
- Tables are plain `div.tableWrapper` scroll regions, the same in the editor (Tiptap) and in read-only Markdown, and are not tab stops:
  - Editors reach every cell with the caret.
  - Keyboard scrolling of a wide read-only table relies on the browser making scroll containers focusable. Chromium 130+ does; `[INFERENCE]` other engines may not.
