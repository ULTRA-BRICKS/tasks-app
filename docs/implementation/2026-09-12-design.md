# Reference-led implementation — 2026-09-12

## Plan and critique

Target: the working Linear issue document, not a marketing page or CRUD dialog.
Public demo inspected in Chromium at 1440×1000, DPR 1, dark theme. Reference source:
https://linear.app/demo/issue/ENG-128/fix-css-in-payment-history
The actual `V` shortcut in this demo opened a tall modal, not a full page. Our user explicitly chooses page-first creation, so that interaction intentionally differs.

Measured detail title: x306.83, y112.5, width653.05, height32. Main shell begins x244, y8. Description actual text shares the title's left edge; its focus surface extends about14px beyond it. Properties begin around x1019. Screenshot capture waited for title visibility and font readiness; the earlier loading frame was rejected.

Palette: sidebar near #080808, content #111111, elevated #1b1b1b, border #232323, readable secondary #a0a0a0, accent #6268df. Values enter the DTCG source, not parallel CSS constants. Typography uses a system sans fallback without redistributing font binaries.

Layout: 244px navigation; inset content shell; one quiet toolbar; centered document with right property rail. New/existing issue use the same text-first components. No feature marketing headlines, permanent editor tabs or global Save bar. Page-first draft remains unpublished until explicit Create.

Critique before coding: merely removing borders from the old form would preserve the wrong workflow. Build shared inline title/Markdown primitives and safe draft persistence first, route creation into them, then tune shared tokens and geometry. Do not copy unrelated Linear menu items for appearance.

## Acceptance

Verify draft recovery, changes typed during saving, stale server versions, repeat create clicks, keyboard/IME, readonly, errors and mobile viewport. Capture actual app screens and overlay against the measured reference region. Different data, avatars, activity timestamps and missing modules are not evidence of geometric error and must be documented, not hidden by claiming a global match percentage.

`frontend-design` was read from Anthropic's official repository before planning. Its explicit-brief rule takes precedence over inventing a novel identity. Review layout and interaction after implementation, not only compilation.
