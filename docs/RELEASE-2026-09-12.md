## Review and adversarial checks

Three read-only reviewer roles covered consistency, correctness/security and performance. Only the findings summary is published; raw agent transcripts and private machine context are not repository evidence.

1. **Card hold:** reproduced as a failing browser test. The eligibility guard had rejected the card button before starting its hold timer. It now admits card/open-control whitespace while still excluding selectable text and unrelated controls. The new regression passes in Chromium and WebKit.
2. **CI browser mismatch:** fixed `test:e2e` to run both configured engines, rather than merely installing WebKit and executing Chromium.
3. **Planning acknowledgement race:** the suggested silent-overwrite scenario was tested with a held v2 PATCH response, a real remote v3 write, and a v3 refetch while v2 remained pending. It passed before any functional draft change. The existing lock prevents adopting v3's version with v2 fields; after unlocking, clean synchronization adopts the complete v3 object. The added regression proves the remote body survives the next edit in both engines.
4. **Old deployment notes:** corrected. The earlier empty-production-database observation was stale: the current public readiness check confirms schema and owner initialization. The old GitHub publisher is disconnected. This release deliberately uses a manual authorized CLI publisher; Forgejo CI does not promise unattended deployment.
5. **Bounded storage throughput:** private Blob download buffering and upload I/O inside a write transaction remain documented limitations. No private attachment authorization bypass was identified in the changed code; this is not a claim of a full security audit.

The follow-up also restores the active Forgejo formatting and visual gates, pins the browser job to the Playwright 1.63.0 Noble container, preserves the verified 30-second PostgreSQL pool wait within an expanded 60-second function deadline, and groups projects in one memoized pass. A unit test enforces the pool-budget relationship. Visual baselines are platform-specific: macOS rendering is not silently substituted for Linux CI.

## Production observations and explicit limits

The existing Vercel project is READY. The canonical domain is public, `/api/ready` returns `200 {"status":"ready"}`, and anonymous `/api/v1/me` returns 401. Production 5xx log queries for the new deployment returned no matching rows in the observed window. The protected owner credential remains on the operator's computer; see [Operations](OPERATIONS.md).
