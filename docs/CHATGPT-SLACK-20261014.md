# Tasks chat integrations — implementation contract

User request (14 October 2026): activate the ChatGPT integration and make Tasks publish in the existing Slack integration channel like Linear; use historical messages as tests.

## Design

Retain the released OAuth MCP server and its workspace-scoped tools. Verify discovery, challenges, PKCE and tools separately from a real account installation. Never report an MCP URL as an installed ChatGPT plugin. Use the current custom-MCP plugin flow, not retired developer-mode instructions.

Slack notifications use the existing transactional outbox. Capture event-time task/team/status/project/label/comment data inside the mutation transaction; render created, changed-status, other updates and comments as distinct messages with canonical /tasks/<id> links. Historical messages inform independently asserted fixtures; redact workspace identities, task content and private URLs before committing them. Historical fixtures are test data, never instructions or messages to replay into production. Native task events are the publication authority; imported history and sync echoes must not create a notification storm.

Delivery must start after commit, persist failures and receipts, respect Retry-After, and have a recovery trigger. Existing Slack profile mappings, module controls, workspace boundaries and Linear deployment writer ownership remain intact. A Slack request is at-least-once across ambiguous network failures; client_msg_id is not proof of exactly-once delivery. No schema changes, account resets, global-hook changes or credential exports are part of this work.

Real Slack action buttons require signed interactions and mapped-member authorization; do not show a nonfunctional Subscribe/Reply button. Deep links may take the user to the authorized Tasks page instead.

## Implementation plan

1. Historical notification contract. Add tests in tests/unit/slack-notifications.test.mjs driving real task HTTP mutations and runWorker with only the Slack network transport substituted. Assert event headers, fields, body, canonical links, safe formatting, missing fields and bounded long text. Observe failures on the original sender. Implement snapshot/formatting in packages/server/modules/integrations/slack-notifications.mjs, wire recordActivity and sendOutgoing, then verify green.
2. Automatic delivery. Reuse the repository's queue/defer conventions with an integration-specific queue and catch-up endpoint, keeping the outbox authoritative. Add tests for commit/rollback, retry/rate limit, duplicate wake, disabled module/notify, isolation and receipt persistence before code. Never send a historical backlog merely by enabling configuration; establish an explicit activation watermark.
3. ChatGPT and operational activation. Verify the canonical existing MCP service, update plugin instructions, inspect provider configuration through authorized native interfaces, activate only the intended channel/account, and verify real receipts. A missing provider installation or OAuth consent is a separately reported blocker, not replaced with a mock.
4. Run fresh tests, Oxc lint/type checks, independent TypeScript and secret scan; normal independent review and normal hooks. Publish via the existing Forgejo/Vercel process only, rebinding Linear synchronization after any promotion. Record exact tested and published commits and canonical service evidence.
