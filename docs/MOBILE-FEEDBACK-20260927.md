`useMobileChrome`, owned by `Navigation`, holds the workspace's only scroll, focus and viewport listeners. One capturing document listener sees document scroll and the board region (`data-content-scroller`); it ignores scrolling outside the touch phone layout (`(pointer: coarse) and (max-width: 767px)`, the same media as the dock and compaction CSS), which never changes the chrome. A ResizeObserver measures the page toolbar marked `data-page-header`; a subtree MutationObserver reconnects it after route changes or late loading. The height is published as `--page-header-height` and the compact state as `data-header-compact`, both on the root element, so neither toggle re-renders the route. There is no per-task observer. Scroll thresholds use named hysteresis constants. Dock direction discounts the header's own resize, so scroll anchoring is not mistaken for scrolling up. Desktop fine-pointer decisions are listed per selector below.

Readability, reduced motion and opaque fallback are part of the contract. Short CSS entrance motion avoids a new animation dependency. Reference: https://motion.dev/docs/react-transitions (CSS-capable duration springs); https://base-ui.com/react/components/popover (existing popup focus/animation conventions).

Evidence: five new browser regressions failed on the unchanged baseline. The first implementation passed 9/10 Chromium/WebKit cases; the remaining assertion compared geometry from different animation frames. It now samples both rectangles together after the real CSS transitions finish, retaining the same tight geometry limits. Fresh final receipts and screenshot inspection are required before release.

### Desktop (fine pointer) decisions

- List group headings: glass is limited to touch and ≤767px layouts. There, the older rule made them transparent while rows scroll beneath them. Wide desktop keeps the opaque panel heading.
- Board column headings stay sticky at every width, because UB-42 requires desktop containers to work. Desktop keeps the original 40px geometry on an opaque canvas background (selected while the column is a drop target), so resting pixels match the baseline. Touch/narrow layouts get the 44px glass pill.
- `.board` equal-height stretch, `max-content` width and the board region's own overflow apply everywhere. Columns have no resting background, so this is invisible at rest. It keeps each column heading stuck for the whole scroll and the end padding reachable.
- The preview action toolbar is horizontal at every width, because `role="toolbar"` declares `aria-orientation="horizontal"` everywhere. Desktop buttons keep their 40px height; touch uses `--mobile-tap`. The 44px close button is mobile-only again.
- The preview surface keeps its light glass and spring entrance everywhere: it is a single overlay with an 88% tint and an opaque fallback.

Desktop proof: the `visual` Playwright project at 1440×1000 compares against the committed darwin baselines. Desktop list, desktop board, task detail, new task and the narrow fine-pointer list matched without baseline changes. Only the touch-phone list changed (1289px, all in the dock region). That change is the intended UB-40 dock: 54px, 4px from the safe edge, 48px create button, 58% glass. That single baseline was updated after inspecting the expected, actual and diff images. The 1440×900 captures (list, list scrolled, board, board scrolled, preview) are external evidence.
